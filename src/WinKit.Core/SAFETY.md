# NUL 清理核心的安全模型与限制

本目录为无 WPF/第三方依赖的 Windows 专用 `.NET 10` 核心。公共契约位于 `NulCleanup/Contracts.cs`。

## 允许的操作

- 仅清理目录枚举所得、名称**精确为 `nul`（匹配时忽略大小写）**的普通文件。
- `null`、`nul.txt`、任意其他文件、名为 `nul` 的目录、所有文件/目录重解析点均不删除。
- 接受 `C:\目录` 和 `\\服务器\共享\目录` 的规范绝对路径，可带一个末尾反斜杠。不接受设备路径/调用者提供的扩展路径、相对路径、正斜杠、`.`/`..`、内部重复分隔符、ADS、尾随空格/点以及保留名目录。
- 删除是永久删除，不经过回收站。调用者负责默认不勾选、展示范围、明确获得用户确认。

## 防越界和 TOCTOU

1. 用内部构造的扩展路径打开磁盘根/UNC 共享根，带 `FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_BACKUP_SEMANTICS`，检查目录及重解析属性。
2. 每层目录以 `NtCreateFile` 的 `OBJECT_ATTRIBUTES.RootDirectory` 相对已验证父句柄打开，带 `FILE_OPEN_REPARSE_POINT | FILE_DIRECTORY_FILE`。不重复解析完整绝对子路径；对象属性不强制大小写不敏感，因此支持启用 NTFS 目录大小写敏感时同目录的 `nul` / `NUL`、`scan` / `SCAN`。
3. 磁盘/共享根、选定根的全部祖先，以及当前递归路径目录句柄仅共享 READ，不共享 WRITE/DELETE，并在相关操作结束前持有。这使 Windows 本地文件系统无法在检查后重命名/删除祖先或修改其重解析数据。权限不足或已有不兼容目录句柄会失败关闭，不绕过检查。
4. 枚举通过 `GetFileInformationByHandleEx(FileIdBothDirectoryInfo)` 在目录句柄上进行。目录/文件必须再以相对句柄打开并复查属性，处理枚举和打开之间的变化。
5. 目标删除句柄包含 `DELETE | FILE_READ_ATTRIBUTES | SYNCHRONIZE`，**共享模式为 0**，先检查普通文件和身份/元数据，然后 `SetFileInformationByHandle(FileDispositionInfo)` 通过同一已验证句柄标记删除；关闭句柄后才报告成功。不使用普通 `File.Delete` 或 shell 删除命令。
6. 扫描身份为卷序列号 + 128 位文件 ID + 创建时间。删除复查此身份，同时要求扫描时的大小和最后修改时间仍一致。目标句柄不共享任何访问，防止普通并发读写/删除操作在核验与删除之间修改目标。它不是密码学内容哈希，不宣称检测恶意内核/驱动或能直接修改底层文件系统的对手。
7. 同一服务实例只授权**最新一次扫描**。记录根目录身份和精确候选路径；无扫描、旧根、被替换的根、伪造的 candidate、越界路径均拒绝。删除候选按大小写精确完整路径绑定，而不是以 Identity 为唯一键；硬链接可共享身份但仍为两个独立候选。

## 边界、失败与取消

- 根的任何祖先若为目录联接、符号链接或其他重解析点，扫描/删除失败关闭。嵌套重解析点不跟随并计入 `SkippedReparsePoints`。若打开失败而无法确认其类型，报告 Issue/Failed 而非猜测。
- **不进入保留设备名目录**，包括名为 `nul` 的普通目录。扫描对此报告 `ScanIssue`，不显示成完整成功。这是有意收窄的第一版范围。
- 最长显示路径 32700 字符，每个组件最多 255 UTF-16 字符，从盘/共享根起最多 256 层目录。超限子目录返回明确 Issue；极端深树不会导致无限句柄增长或递归爆栈。
- 不提权，不清只读属性，不绕过 ACL/共享限制；逐项 `Failed` 并含 Windows 错误码，某项失败不阻断其余项。
- 目标或相对目标父目录在核验后不存在 => `AlreadyMissing`。扫描根消失/无法重新安全打开不意味着所有目标缺失，而是 `Failed`；发现根身份变化/重解析点 => `Refused`，需重新扫描。
- 取消扫描保留已找到的候选并设置 `WasCancelled`。部分扫描的候选可以由调用者明确确认后删除；未访问区域不会被授权。取消删除会把未执行项逐项标为 `Refused`；已经完成的删除不可撤销。
- 每实例串行化扫描/删除；等待前一个操作期间收到的取消在取得锁后返回部分/拒绝结果，不采用抛异常丢失结果。进度通知异常作为 Issue，不破坏文件操作。
- 不处理映射到虚拟/不可靠设备、文件 ID 信息不支持或服务器不能保证 Windows 句柄共享语义的文件系统。UNC 使用同样的句柄/身份检查；本机测试未覆盖真实网络共享、DFS 或 SMB 服务端恶意改写。共享根以上的服务端文件系统祖先无法从客户端审计。盘符/共享根只初次解析一次，所有下级操作相对句柄锚定；本机卷重新挂载/断连可导致操作失败，不能保证显示路径在外部命名空间改变后仍映射同一根。
- 可写内存映射、管理员/内核/离线磁盘修改不属于承诺的保护边界。不会自动释放其他进程占用、改变文件系统或做系统级修复。

## 验证

无测试框架依赖的回归程序位于 `tests/WinKit.Core.Tests`，仅创建随机临时树，清理时验证自有边界且不递归进入重解析点。测试不会扫描或删除用户现有的 NUL 问题文件。
