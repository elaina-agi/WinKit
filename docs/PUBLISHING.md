# 公开仓库发布检查

本仓库公开的是源码、构建脚本、原创图标与项目文档。仓库内的 SDK、EXE、压缩包、测试截图、日志和本机配置不纳入 Git；如需分发编译程序，应先单独检查发布包，再通过 GitHub Release 附件发布。

## 忽略范围

- 仓库内 SDK、`artifacts`、`bin`、`obj`、发布目录、测试输出。
- IDE 状态、用户设置、临时文件、崩溃转储和 Python 缓存。
- 真实环境配置、签名私钥/证书、凭据文件。
- 运行时 `settings.json` 与 `operations.jsonl`。日志和截图可能包含完整文件路径，不应上传。
- 意外创建的大小写变体 `nul` 文件。正常的 `null` 文件不在此规则内。

`.env.example` 和 `.env.template` 可以跟踪，但只能放无效的占位符，绝不能放真实凭据。忽略规则只防止新增文件被默认加入，不会清除已经提交的内容，也不能识别任意文件名中的秘密。

## 每次公开推送前

1. 检查 `git status --short`、`git diff --cached` 和实际跟踪列表，确认只包含预期源码。
2. 检查密钥/令牌/密码、私人邮箱、本机用户目录、内部地址、配置、截图和日志。
3. 首次推送检查所有将推送的提交；之后检查新增提交，不能只看当前工作区。
4. 提交身份使用 GitHub 提供的 noreply 邮箱，不暴露私人邮箱。
5. 按功能或维护目的分批提交。不要用 `git add -f` 绕过忽略规则添加本机生成物。
6. 运行构建和相关测试；涉及界面时检查真实窗口与主题，涉及删除时只使用自己创建的临时测试目录。

可检查忽略规则：

```powershell
git status --short --ignored
git ls-files -ci --exclude-standard
git check-ignore --verbose -- .env artifacts/example.png signing/release.pfx
```

`git ls-files -ci --exclude-standard` 正常应无输出。任何已跟踪的敏感文件必须在推送前另行处理；仅添加忽略规则不够。

## 首次发布审计

首次发布前检查源码及已有功能/主题提交历史；未发现真实凭据、私人邮箱、本机用户名路径或会话内容。提交邮箱使用 GitHub noreply。仅跟踪的二进制素材是原创应用图标，实际窗口截图和发布程序均处于忽略目录。

该检查不等于对所有形式的敏感信息作绝对保证。若之后发现已公开的凭据，先撤销/轮换凭据，再处理历史和协作方副本；不要只删除最新文件。
