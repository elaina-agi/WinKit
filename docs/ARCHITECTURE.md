# WinKit 架构

## 目标

一个可以持续添加实用小功能的 Windows 桌面工具箱。首版只提供完整可用的 NUL 清理工具，不为尚不存在的功能添加占位入口。离线运行、无需账号，默认普通用户权限。

## 结构

```text
WinKit.slnx
├─ src/
│  ├─ WinKit.Core/          原生安全文件操作；不依赖 WPF
│  └─ WinKit.Desktop/       WPF 应用壳、工具注册、视图与公共桌面服务
├─ tests/
│  ├─ WinKit.Core.Tests/    临时目录中的真实 Windows 文件回归测试
│  └─ WinKit.Desktop.Tests/ UI Automation 实际操作窗口与确认框
├─ scripts/                SDK 准备、编译、测试、发布
├─ assets/                 应用图标
└─ docs/                   使用与设计说明
```

## 分层

1. **应用壳**负责导航、窗口生命周期和统一视觉资源，不实现具体的文件删除。
2. **工具模块**自行提供描述、视图与视图模型。NUL 清理有扫描/选择/删除流程，但不要求未来工具也使用这个流程。
3. **公共桌面服务**提供对话框、配置、日志和命令基础设施。日志写入失败不能改变文件操作的真实结果。
4. **核心**只接收明确路径及扫描候选，返回扫描问题和逐项删除结果。界面层不绕过核心安全核验。

## 添加工具

- 在桌面项目的工具模块目录添加独立视图、视图模型和工具描述，加入工具注册表。
- 将可独立验证的操作逻辑放入 Core 的新命名空间，不引用 WPF 类型。
- 复用路径选择、任务状态、确认提示和记录能力；不要把所有工具都做成通用扫描器的特例。
- 为新操作添加测试。如果操作会修改数据，先明确作用范围、预览、确认和失败语义。
- 新分类只有实际工具时才展示。第一版不使用外部动态插件，后续有真实需求再决定接口。

## 主题

共享 `ThemeService` 由应用启动时根据本地配置初始化，应用壳与设置页共享同一实例。颜色资源集中于 `Themes/Light.xaml` 与 `Themes/Dark.xaml`，两个字典必须具有相同资源键。

已有视图通过 `DynamicResource` 读取语义画刷，切换只替换应用合并字典，不重建工具视图、不重新扫描、不更改勾选。新增模块必须复用这些语义资源，避免硬编码浅色背景或黑色文本。主题选择存储为 `UseDarkTheme`，旧配置缺少该字段时默认浅色；保存失败时当前主题仍可使用，并提示未能记住。

系统文件夹选择和删除确认仍采用 Windows 原生对话框，不因主题变化绕过或替换安全确认。

## NUL 清理不变量

- 仅精确文件名 `nul`（忽略大小写）；不包含 `null`、`nul.txt`、名为 `nul` 的目录或重解析文件。
- 根目录和祖先路径都要验证。不跟随符号链接、目录联接或其他重解析点。
- 使用扩展路径访问真实磁盘文件，使用原生句柄获取文件身份及进行删除。
- 删除前核对最新扫描记录、根目录和目标文件身份，同时核对大小和最后修改时间；按精确路径绑定候选，避免硬链接或大小写敏感目录混淆。拒绝越界路径、被替换的对象或重解析路径。失败宁可拒绝，不尝试“智能修复”安全检查。
- 普通权限运行；只读或被占用时报告失败，不悄悄提权、解锁或改属性。
- 删除不经过回收站；初始不勾选，用户选择后必须确认。
- 取消扫描保留已发现结果，同时明确标注扫描不完整。扫描问题不等于“没有 NUL 文件”。

## 发布

.NET 10 LTS、Windows x64、自包含单文件发布，不启用 WPF 不兼容的裁剪。运行时的原生组件可能在首次启动时解压到 .NET 的本地缓存，因此“单文件交付”不表示运行期间绝不产生其他文件。配置和日志存放于用户本地应用数据目录。
